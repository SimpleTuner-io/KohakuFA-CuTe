# Tuned long attention on A100

The optional SM80 backend improves A100 forward and joint backward while
preserving the [default arithmetic](precision.md). It adapts the pinned
FlashAttention warp-MMA design into static derived methods. The original public
FA4 backward interface excludes SM80; this is a KohakuFA-CuTe implementation,
with standalone FlashAttention-2 as its A100 competitor.

## Installation and selection

The qualified stack is Python 3.13, PyTorch 2.15.0+cu132, CUTLASS DSL 4.8.1, TVM FFI
0.1.15.post0, quack-kernels 0.6.5, and torch-c-dlpack-ext 0.1.5. Install the pinned
optional dependency from the repository:

```sh
python -m pip install '.[cuda,sm80-fa4]'
```

The source revision is
`4616f5116d33e3ba3cbb71d582caffcfcb49649c`. Runtime version and source checks
keep an unqualified installation on the existing native CuTe path. A selected
backend's execution errors propagate.

Initial automatic selection is limited to full 108-SM A100 devices, batch one,
8–16 equal query/key/value heads, contiguous square FP16/BF16 inputs with
16-byte-aligned starting addresses,
D64/D128, and sequence lengths 2048–4096. Causal D128 with fewer than 16 heads
requires length 4096: its shorter forward calls had no wall-time improvement.
The backend accepts finite scales in `(0, 2e38]` (or the positive default) and dense or causal visibility. Explicit
masks, GQA, signed or zero scales, other shapes, deterministic mode, and
`torch.compile` retain the existing native path. The automatic API continues
to use SDPA for inputs unsupported by CuTe as a whole.

## Design and arithmetic

Forward uses a 128×64 score tile, four warps, one K/V stage, and Q in shared
memory. It shifts scores by the unscaled maximum before applying the scale and
exports the literal maximum and shifted log2 normalization separately.

Backward uses a 64×128 score tile and eight warps. The joint loop performs QK,
dP, dV, dQ, and dK products while sharing their reconstructed probabilities.
Q and dO each have two stages. One packed input-dtype P fragment feeds both dS
and dV; dS converts once before the gradient products. Products accumulate in
FP32, actual rounded O and dO define the FP32 delta, and dQ/dK scale after
accumulation. No residual products or compensated policy are selected.

The dQ conversion reconstructs the main kernel's eight-warp scratch layout.
Using the inherited four-warp postprocess permuted dQ despite passing dK/dV.
Visibility uses the actual query/key fragment coordinates, including partial
tiles; it avoids an inherited mask-layout mismatch. Returning the owned output
allocation allows changed-input graph replay and output poisoning without a
custom-autograd view alias.

The shared implementation exposes independent Q/dO stage counts and MMA warp
layouts for subsequent device qualification. Its public selector currently
enables A100 only. Shared storage is checked against the actual device limit.
There is no runtime source rewriting.

## Measured comparison

Measurements used a full A100-SXM4-40GB, 108 SMs, and a 300 W power limit.
The explicit static-kernel matrix contains 24 cases: FP16/BF16, 16 heads, lengths 128/1024/4096,
D64/D128, and dense/causal visibility. Five warmed CUDA-graph timing rounds
used 100 ms windows, rotating backend order. The device timing boundary includes forward,
backward preparation and dQ conversion, or their combined call as labelled.

### Complete eager calls

Python preparation changes the short-call ranking. At BF16, 16 heads,
S128/D128 dense, warmed eager forward took 16.8 µs for generic CuTe versus
65.0 µs for the static wrapper. Combined forward/backward took 60.8 versus
172.9 µs. These short cases remain on native CuTe automatically. Their faster
captured GPU work is available to the explicit benchmark factory.

A separate wall-time sweep covered FP16/BF16, 8/16 heads, lengths
1024/2048/4096, D64/D128, dense/causal visibility, and forward/combined calls.
It alternated backend order over five windows of ten complete eager calls,
synchronizing before and after each window. Compilation, allocation warming,
and initial execution were separate. The selected long families improved
wall time by 1.16–1.81× across measured forward and combined cases. The
medium causal exception above retains the native path.

Device-event samples and wall samples remain separate in the summary. Graph
speedups for short shapes do not describe automatic eager dispatch. The
[host launch contract](sm80-host-abi.md) records the arguments and buffer
ownership for reducing preparation overhead without changing GPU arithmetic.

A matched same-process SDPA eager comparison verified the actual default
backend with a separate CUDA-profiler capture for every row. All 48
forward/combined rows selected PyTorch FlashAttention, with
`aten::_scaled_dot_product_flash_attention` and its backward operator.
Profiling was outside the timed windows.

## Qualification and profiling limits

The static implementation passed 74 directed cases spanning both input dtypes,
negative common offsets, partial tiles, signed/zero native fallbacks,
rounded-cancellation and FP16-underflow fixtures, literal saved statistics, and
changed/poisoned graph inputs. Output and each gradient retain the independent
per-head 1% BF16 or 0.5% FP16 norm gates. Directed rounding checks use actual O.
All 24 timing rows passed their independent correctness checks. Final public
tests verify repeated strict/automatic calls, actual captured static symbols,
and compiled graphs that retain the native backend. Memcheck,
racecheck, synccheck, and initcheck passed the changed-graph/tail smoke set with
zero reported errors or hazards.

Systems confirms one forward kernel and three backward kernels: delta/scratch
preparation, the joint main loop, and dQ conversion. FA2 has the same backward
launch count and 64×128 main geometry. For D128 the observed main kernels both
allocate 255 registers per thread; the optional main uses 164864 shared bytes
versus FA2's 147456. Its graph resource query reports 24 local bytes per thread.
These facts identify resource and scheduling differences; they do not measure
stall percentages or establish a hardware ceiling.

Compute counters were denied with `ERR_NVGPUCTRPERM`. Compiler-returned PTX and
cubin were retained, and graph CUfunction resources were queried. The Python
loader hook did not observe TVM FFI's image loads, so exact loaded-image hashes
remain unbound. Static instruction analysis must keep that distinction.

Two-stage forward and register-resident Q variants generally regressed; their
combination failed correctness and remains an experiment. Positive-only
probability specialization gave no broad material improvement. Producer-owned
maximum staging passed correctness and sanitizers, but improved some D128 and
causal rows by only 1–3% while slowing D64 dense. It is retained separately and
is not selected by this backend. One dO stage reduced D128 shared storage to
148480 bytes and local storage to 16 bytes per thread. Its small gains varied
by dtype; the two-stage default remains selected, with the one-stage schedule
retained as an explicit experiment.

## Reproduction

With the qualified stack and an A100:

```sh
python -m unittest tests.test_fa4_sm80 -v
python -m benchmarks.validate_sm80_static --direct --output artifacts/a100-directed.json
python -m benchmarks.compare_flashattention \
  --backends cute fa2 sdpa --seq 128 1024 4096 --dim 64 128 \
  --dtype bf16 fp16 --modes dense causal --repeats 5 --window-ms 100 \
  --candidate benchmarks.static_sm80_experiments:make_attention \
  --output artifacts/a100-static.json
```

The explicit comparison factory keeps generic CuTe as the baseline within that
benchmark process and calls the static candidate directly. Public-dispatch
qualification runs separately without that control override. The comparison
driver is included with the standalone FlashAttention benchmark tools in this
repository.
