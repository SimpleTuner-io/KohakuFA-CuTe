# RTX 3090

Use the explicit entry on the [pinned runtime](../installation.md#qualified-tuned-runtime):

```python
from kohakufa_cute import rtx3090_attention
out = rtx3090_attention(q, k, v, is_causal=True)
```

## Selection

The target is an ordinary full 82-SM RTX 3090. Inputs are contiguous, aligned,
equal-shape FP16/BF16 tensors with B1/H16, no mask/dropout, and a positive normal
FP32 scale. Dense and causal training are qualified:

- S128 at D16/D64/D128 uses owned-gradient short kernels.
- S1024–S4096 at D64/D128 uses native-host shared warp-MMA schedules.

Masks, GQA, unsupported scales/layouts, compiled calls, and other shapes retain
ordinary CuTe dispatch. RTX 3090 Ti is a separately qualified target.
Long causal ordering uses G16 at S1024 and G4 above that length. Short D128
uses its qualified saved-statistics staging. Arithmetic follows
[the standard contract](../precision.md).

## Evidence

[The RTX 3090 report](../../results/rtx3090.json) retains long graph/eager calls
at S1024/1025/2048/4096 and the latest short studies for each width. Comparisons
include actual public entrypoints, FA2, and SDPA on identical rounded inputs.
Long causal D128 still trails FA2 in some measured cases; eager overhead can
limit graph improvements.

Qualification includes changed poisoned graphs, statistics, per-head FP64
component checks, negative views, and all four sanitizer tools. Expected final
FP16 overflow fixtures remain separately labeled in the report.

Run `tests.test_rtx3090_optin` and the relevant short-owner tests for changes;
use `benchmarks.experiments.ampere.compare_rtx3090_optin` for matched complete-call measurement.
