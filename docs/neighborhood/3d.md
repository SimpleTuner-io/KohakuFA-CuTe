# 3D neighborhood attention

The 3D path extends the existing neighborhood owners across time, height and
width. It uses the same separate score maximum/log normalization, FP32
accumulation, normalized dQ correction and reconstructed dK correction as 2D.
3D forward also uses two input-dtype terms for each FP32 probability weight,
reducing the error introduced by rounding that weight before multiplication by V.
The [precision contract](../precision.md#neighborhood-default) defines both methods.
No mask or neighborhood index table is materialized by the implementation.

## Calling from LTX

`neighborhood_attention_3d` accepts the LTX diffusion decoder's
`[batch, time, height, width, heads, 64]` layout:

```python
from kohakufa_cute import neighborhood_attention_3d

# Q/K/V have already passed through the decoder's normalization and RoPE.
# LTX folds 1/sqrt(64) into its Q normalization weight, so do not scale again.
out = neighborhood_attention_3d(q, k, v, (3, 7, 7), None, 1.0)
```

This is an explicit attention replacement; installing this package does not
change SimpleTuner's backend selection. Keep the surrounding projections,
normalization, RoPE and output projection unchanged. The adapter supports
first-order autograd, although LTX's current in-place RMS/RoPE helper itself
is inference-only.

Like the decoder's `na3d` helper, the adapter clips each requested window to
its axis length. For example, `(11, 11, 11)` on `(1, 8, 16)` becomes `(1, 8, 11)`.
This is a documented convenience relative to [NATTEN's strict window-size
requirement](https://natten.org/operations/). Windows then shift inward at
boundaries, maintaining a fixed number of visible keys. Even windows use
`window//2` as their anchor. Temporal boundaries are asymmetric too: dK/dV
find all queries attending a key rather than applying its forward window.

Q/K/V must match in shape and FP16/BF16 dtype on a supported CUDA device.
Head dimension is 64, with equal query/key/value head counts. Only noncausal,
stride-one, dilation-one attention is supported. `is_causal` accepts `None`,
`False`, or three `False` values; causal requests raise an error. Masks,
relative bias, dropout and higher-order gradients are unsupported. The default
scale is `1/sqrt(64)`; use `1.0` for the already-scaled LTX operands.

The adapter uses views for the contiguous LTX layout. Other strided inputs
are accepted, but flattening their spatial dimensions can require a copy.
Output has the same logical shape and dtype as Q; contiguous storage is not
promised.

## Flattened API

The original API also accepts three spatial dimensions:

```python
from kohakufa_cute import neighborhood_attention

# Q/K/V: [batch, heads, time * height * width, 64], width varies fastest.
out = neighborhood_attention(
    q, k, v, spatial_shape=(time, height, width), window_size=(3, 7, 7), scale=1.0
)
```

This form requires the supplied window to fit every axis; it does not clip.
2D calls retain their original semantics and scheduling. 3D uses the generic
neighborhood owner plus compact spatial forward owners for qualified large-window
workloads. H100 PCIe uses an 8×8 patch; A100 PCIe 40 GB, RTX 3090, RTX 4090 and
L40S use a 4×8 patch. Both use the same two-term forward and corrected backward
arithmetic. The [H100 comparison](reports/ltx-3d.md) and
[Ampere/Ada tile study](reports/3d-tiles.md) record the exact device/shape gates,
complete-call timings and FP64 checks; 2D evidence does not qualify 3D.

## Qualification

[3D tests](../../tests/test_neighborhood_3d.py) independently enumerate legal
windows and reverse their edges, covering even windows, plane seams, tails,
strided views, signed/zero scales, changed graph inputs, and compiled geometry
changes. GPU tests check each output and gradient separately against the
corrected-policy reference and, for random inputs, mathematical FP64.

Run on a remote CUDA host using the [pinned neighborhood stack](README.md#reproduce-and-inspect):

```sh
python -m unittest tests.test_neighborhood_3d tests.test_neighborhood_volume_forward -v
python -m benchmarks.neighborhood.qualify --dimensions 3 \
  --source-revision "$(git rev-parse HEAD)" --output "$CAPTURE_DIR/3d.json" \
  --reference-agreement --compare-natten --natten-backend cutlass-fna --profile
```

The runner covers `(3, 7, 7)`, `(3, 5, 5)` and `(11, 11, 11)` LTX window
families plus even-window and common-offset probes. References evaluate
identical rounded inputs in native FP64, not emulated precision. The separate
policy reference retains the specified rounding and uses actual rounded O.
Random-input per-head norm limits are 0.5% FP16 and 1% BF16, independently for
O/dQ/dK/dV. Directed fixtures check the declared corrected equations; their
FP64 diagnostics are not universal error bounds. NATTEN is a comparison
implementation, not the oracle. These synthetic operator checks do not
establish complete-decoder output quality or performance.

## Initial H100 correctness results

These historical results used the original single-term 3D forward. The
[new forward qualification and LTX timings](reports/ltx-3d.md) are separate.
The [qualification receipt](../../results/neighborhood/3d-h100.json) records
28 candidate cases, each passing its independent per-head/component gates
with both CPU and CUDA references. The remote CPU suite passed 540 tests
(234 CUDA skips); the focused GPU/reference suite passed 47 tests. Six LTX
helper replacement cases also passed against FP64. Memcheck, racecheck,
initcheck and synccheck each passed the FP16/BF16 strided temporal-seam
fixture with zero reported errors (racecheck: zero hazards). These initial results
qualify H100; the later [Ampere/Ada study](reports/3d-tiles.md) records its own
source snapshots and checks.

Worst per-head mathematical FP64 norm errors on four **positive-scale random**
3D geometries per dtype (percent; two heads per case):

| Implementation | Dtype | O | dQ | dK | dV |
| --- | --- | ---: | ---: | ---: | ---: |
| KohakuFA | FP16 | 0.0210% | 0.0275% | 0.0310% | 0.0273% |
| NATTEN CUTLASS | FP16 | 0.0211% | 0.1008% | 0.1004% | 0.0273% |
| KohakuFA | BF16 | 0.1663% | 0.2138% | 0.2533% | 0.2182% |
| NATTEN CUTLASS | BF16 | 0.1668% | 0.7969% | 0.7648% | 0.2183% |

In the positive-scale common-offset probe, dQ error was 0.0272% FP16 and
0.2177% BF16 for KohakuFA, versus 4.8474% and 36.5470% for NATTEN. This is a
directed cancellation stress test, not a measured LTX activation distribution.
The LTX helper comparison used pre-scaled Q and `scale=1.0`: worst dQ errors
were 0.0290%/0.2336% for KohakuFA versus 0.0306%/0.2476% for the existing
SDPA helper (FP16/BF16). Improvements depend on the workload and component;
these results do not establish a universal accuracy advantage.

The pinned NATTEN backend failed all 18 nonpositive-scale probes. Those
failures and operands are retained separately and excluded from the table;
they do not count as accuracy gains. Profiling recorded actual CUDA kernel
launches for all 56 candidate/comparator calls. Compilation, layout conversion
costs and complete-decoder latency were not benchmarked in this qualification.
