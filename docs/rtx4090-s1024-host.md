# RTX 4090 S1024 public-call overhead

The S1024 D64/D128 path now improves actual public forward-plus-backward calls,
including eager execution. It uses the existing GPU schedules and arithmetic.
The change combines a live metadata predicate and the existing native Runner
call behind one Python/C++ boundary, while caching only the immutable Runner
configuration and function handle.

The domain is full RTX 4090, B1/H16, square S1024, D64/D128, FP16/BF16, contiguous
16-byte-aligned inputs, gradients enabled with at least one requested input
gradient, no mask or dropout, and a positive normal FP32 scale. Equal-head MHA
works with either `enable_gqa` value. The pinned Python 3.13/PyTorch 2.15.0/CUDA
13.2 optional runtime is unchanged. Unsupported inputs, NoGrad, inference mode,
compiled calls, determinism, signed/zero scales and other runtimes keep their
preceding paths. Selected-path initialization errors propagate.

## Why the preceding candidate lost eager time

The initial automatic candidate improved S1024 graph replay but regressed
complete eager calls by about 1–4%. Systems confirmed four tuned launches versus
three generic launches, including gradient preparation and conversion. The
instrumented traces also spent substantial time in kernel-name callbacks, so
their durations were not used as sustained performance estimates.

A bounded host comparison retained identical GPU work while varying the caller:
actual public API, explicit Python selector, live native predicate, fixed native
Runner, and one guarded native call. Fixed-factory controls improved eager time
by 1.15–1.17×, but they did not include the complete public dispatcher. The final
public implementation was measured separately on independent inputs.

The actual public route improves eager F+B by **4.8–6.6%** and graph F+B by
**1.28–1.76×** across all eight selected cases. The graph gain comes from selecting the existing tuned GPU programs. The host
change makes that selection a net eager improvement; all four tuned GPU launches
remain. GPU arithmetic and kernels are unchanged. The [complete record](../results/rtx4090-s1024-host.json) keeps
both experiments, all timing samples and actual launched-kernel resources.

FA2 and SDPA retain their native arithmetic policies; their columns compare
complete implementations. BF16 timings are microseconds; lower is better:

The full default grid now records **56/60 forward** and **52/60 backward and
combined** wins against SDPA. Its eight changed S1024 cells use the new actual
public graph measurements, with explicit source and protocol per cell. The
other 52 cells retain their qualified measurements. The earlier cohort uses
five 100-ms windows; the updated eight cells use seven 80-ms windows. Forward
retains autograd in both cohorts. Comparisons are within each cell on the same
GPU and stack; this does not claim a controlled cross-GPU speedup.

## Validation and code binding

All three actual public namespaces passed output/dQ/dK/dV checks on identical
rounded operands, with independent per-head FP64 limits of 1% BF16 and 0.5% FP16
and the declared rounded equations retained as diagnostics. Inputs and all
source/runtime/commands were saved before execution. Tests covered live gradient
flags, mutable storage offsets, cached metadata, Parameter inputs, unsupported
layouts and dimensions, masks, GQA, rectangular shapes, signed/zero scales,
NoGrad/inference mode, deterministic/runtime guards and compiled bypass.
Changed-input graph replay is checked by the timing driver.

Four exact selected BF16 backward symbols were bound to loaded cubin bytes and
compiler-returned artifacts, with PTX/SASS retained. The mapped native host
extension and complete raw archives are SHA-verified. GPU scheduling, ownership,
barriers, the 14-tensor FFI and the operand-conversion policy are unchanged;
previous GPU sanitizer qualification remains applicable. This change retains
single-rounded P before dS, single-rounded dS, FP32 products and actual-O delta,
and scaling after dQ/dK accumulation.

The initial fixed-factory control and final public measurements are separate.
Profiler captures are outside timing windows.
